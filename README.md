# Livelyrics — 為樂團打造的舞台歌詞視覺

上傳一首歌，AI 會以「樂團專職舞台視覺設計師」的角度研究歌曲與樂團，設計**主視覺**、每一段的**背景動畫**，以及**歌詞如何跟著主視覺呈現**。演出時，你在自己的電腦上用**控制台**操作（完整資訊、跳歌詞、黑場、覆寫場景），投影機上的**投影視窗**只顯示動畫與歌詞。

- 音訊分析（BPM、節拍、能量、段落、波形）在瀏覽器完成。在本機執行時音檔只存在你的電腦上；部署到 Vercel 時存在你自己的 Vercel Blob 儲存空間。
- 歌詞：自動從 [LRCLIB](https://lrclib.net) 找同步歌詞，或貼上 LRC／純文字，再用「對拍」功能自己對時間。
- 設計：有 Claude API 金鑰時由 Claude 上網研究再設計；沒有金鑰時使用**免費研究模式**（查詢 MusicBrainz 與維基百科的公開資料，再分析歌詞意象、情緒與音訊，由內建設計師依這些發現產生方案），一樣能完整使用。想要 Claude 的研究又不想付 API 費用，可以用「**用 claude.ai 研究**」：把提示詞貼到自己的 claude.ai 對話，再把回覆貼回來。

## 在本機執行

需求：[Node.js](https://nodejs.org) 20.9 以上（建議 22 LTS）、Chrome 或 Edge（投影視窗使用 WebGL）。

```bash
git clone https://github.com/alanwu14832-bit/Livelyrics-.git
cd Livelyrics-
git checkout claude/epic-meitner-e2pdib   # 合併進 main 之前
npm install
npm run dev
```

打開 <http://localhost:3000>。

### 啟用 Claude 研究與設計（選用）

在專案根目錄建立 `.env.local`：

```bash
ANTHROPIC_API_KEY=sk-ant-...
# 只有金鑰沒有綁定單一 workspace 時才需要（錯誤訊息會說「沒有綁定 workspace」）
# ANTHROPIC_WORKSPACE_ID=wrkspc_...
# 選用：換模型（預設 claude-sonnet-5-5；要最好的品質可改 claude-opus-5-5，費用約兩倍）
# LIVELYRICS_MODEL=claude-sonnet-5-5
# 選用：Claude 暫時無法使用（503／過載）時，重試兩次後改用的備用模型（預設 claude-opus-5-5；off 關閉）
# LIVELYRICS_BACKUP_MODEL=claude-opus-5-5
# 選用：資料存放位置（預設 ./data）
# LIVELYRICS_DATA_DIR=/path/to/livelyrics-data
```

存檔後在終端機按 `Ctrl+C`，再重新執行 `npm run dev`。首頁右上角會從「免費研究模式」變成「Claude 已連線」。

### 先用示範歌曲試試

`npm run dev` 執行中時，另開一個終端機：

```bash
node scripts/seed-demo.mjs
```

它會用 `fixtures/demo-song.wav` 與 `fixtures/demo-lyrics.lrc` 建立一個示範專案，並印出控制台網址。也可以直接在首頁把 `fixtures/demo-song.wav` 拖進上傳區、貼上 `fixtures/demo-lyrics.lrc` 的內容（這樣會在瀏覽器做完整的音訊分析，時間軸會有波形）。

## 部署到 Vercel（雲端模式）

本機執行不需要任何設定。部署到 Vercel 時，函式的檔案系統是唯讀且不會保留的，所以 Livelyrics 改用雲端模式：作品、樂團與演出存在 Postgres（Neon），音檔與素材由瀏覽器**直接上傳到 Vercel Blob**（函式的請求內容上限約 4.5 MB，檔案不經過函式）。兩種模式的資料互不相通，雲端一開始是空的。

1. 在 Vercel 匯入這個 repo（Framework Preset：Next.js，其餘用預設值）並部署一次。
2. 專案的 **Storage** 分頁：
   - 建立 **Blob** 儲存空間，存取權限選 **Public**（建立後不能更改，Private 不支援），連接到這個專案。會自動加入 `BLOB_READ_WRITE_TOKEN`。
     較新的 Blob 連接只會加入 `BLOB_STORE_ID`（OIDC）與 `BLOB_WEBHOOK_PUBLIC_KEY`，沒有讀寫金鑰；上傳簽章仍需要它，所以首頁會顯示「Blob 已連接，但缺少讀寫金鑰」：到 **Storage ›** 這個 Blob store 的 **.env.local** 分頁（或 **Settings**）複製 `BLOB_READ_WRITE_TOKEN`，加到專案的 Environment Variables（Production、Preview）後重新部署。
   - 從 **Marketplace** 加入 **Neon**（Postgres），連接到這個專案。會自動加入 `DATABASE_URL`（也接受 `POSTGRES_URL`、`DATABASE_URL_UNPOOLED`、`POSTGRES_URL_NON_POOLING`）。資料表 `livelyrics_docs` 在第一次使用時自動建立。
3. **Project Settings › Environment Variables** 加入：

   | 變數 | 說明 |
   |---|---|
   | `LIVELYRICS_PASSWORD` | 建議設定：整個網站需要先輸入這個密碼（登入後保持 30 天，改密碼會讓所有人登出）。沒設定時任何知道網址的人都能使用 |
   | `ANTHROPIC_API_KEY` | 選用：啟用 Claude 研究與設計；沒有時使用免費研究模式。建立金鑰時把它綁定到一個 workspace（例如 Default）最簡單 |
   | `ANTHROPIC_WORKSPACE_ID` | 只有金鑰沒有綁定單一 workspace 時才需要：填 `wrkspc_` 開頭的 workspace ID（Claude Console 的 **Settings › Workspaces**）。沒填時 Claude 會回應 400「沒有綁定 workspace」 |
   | `LIVELYRICS_MODEL` | 選用：換模型（預設 `claude-sonnet-5-5`；要最好的品質可改 `claude-opus-5-5`，費用約兩倍） |
   | `LIVELYRICS_BACKUP_MODEL` | 選用：Claude 暫時無法使用（503、529 過載）時，先等 3 秒、8 秒重試兩次，再改用這個備用模型試一次（預設 `claude-opus-5-5`，只在出錯時才用；填 `off` 關閉） |
   | `LIVELYRICS_BLOB_DELIVERY` | 選用：設成 `proxy` 時音檔與素材經由函式轉送，預設 `redirect` 直接從 Blob 讀取（見下方） |
   | `LIVELYRICS_STORAGE` | 選用：`cloud` 或 `local` 強制指定模式；一般不需要 |
   | `LIVELYRICS_FREE_SOURCES` | 選用：設成 `off` 時免費研究不查 MusicBrainz 與維基百科（也不查 Cover Art Archive 的封面），只分析歌詞與音訊 |
   | `LIVELYRICS_VISUALS` | 選用：設成 `off` 時研究不下載樂團的封面、MV 截圖與主視覺（見「研究找到的素材」） |

4. 每次新增或修改環境變數後都要重新部署（**Deployments › ⋯ › Redeploy**）才會生效。

還沒設定好儲存空間時，首頁會顯示設定說明，API 會回應 503 並說明缺少哪一項；`/api/status` 會回報目前的儲存模式（`storage.mode`：`local`、`cloud` 或 `unconfigured`）。

限制與注意事項：

- 每個處理步驟（取得歌詞、研究、設計）是一次獨立的請求，最長 300 秒（Hobby 方案加 Fluid compute 的上限）。瀏覽器依序送出每一步，每一步的結果都存在作品上：重新整理或關掉分頁再回來，設計總覽會接上進行中的步驟；超過時間沒完成的步驟會顯示「重試」，從那一步繼續。從作品產生視覺聖經、整場弧線也一樣。
- Claude 在每一步最多使用約 250 秒，超過就改用免費研究與離線設計完成這一步（處理紀錄會寫明），不會因為逾時而失敗。免費研究的公開資料查詢最多約 15 秒。
- 音檔上限 200 MB、素材單檔 500 MB。上傳後伺服器會檢查檔案開頭的格式，不是音檔或圖片／影片的檔案會被拒絕並從 Blob 刪除。刪除作品、素材或樂團時，Blob 上的檔案也會一起刪除。
- 播放時，音檔與素材的網址會轉址（307）到 Blob 的公開網址，由 Blob 的 CDN 直接提供（支援 Range，回應帶 `Access-Control-Allow-Origin: *`）；頁面以 `crossOrigin="anonymous"` 讀取，WebGL 材質、Web Audio 與匯出都能正常使用。如果某個網路或瀏覽器擋住轉址，把 `LIVELYRICS_BLOB_DELIVERY` 設成 `proxy` 後重新部署。
- Vercel 的 Hobby 方案只限個人、非商業用途；樂團的商業演出請改用 Pro 方案。
- 演出時仍建議用本機模式或事先在場地網路測試過：雲端模式的控制台與投影視窗需要連線才能載入音檔與素材。

## 使用流程

1. **首頁**：拖放音檔 → 自動讀取曲名／歌手並分析音訊 → 選歌詞來源（自動搜尋／貼上歌詞／之後再處理）→「開始製作」。下方的**作品庫**列出所有作品，點卡片開啟，卡片的「⋯」選單有編輯歌詞、設計總覽、重新處理與刪除。
2. **設計總覽** `/p/<id>/process`：即時看到研究進度（Claude 的搜尋關鍵字與研究筆記）與設計結果（主視覺、色盤、視覺符號、段落規劃）。
3. **控制台** `/p/<id>`：
   - 左：依段落分組的歌詞，點一下就跳到那一句
   - 中：投影畫面即時預覽，下方是「現在／下一句」大字和下一個操作提示倒數
   - 預覽下方的**段落列**：點一個段落就跳過去（`PgDn`／`.` 下一段、`PgUp`／`,` 上一段）。「保持」（`H`）讓畫面停在這一段（場景、配色、歌詞樣式、素材），歌詞照常跟著時間或 cue 前進，適合樂團臨時多唱一次副歌；再按一次回到目前時間的段落。「循環」（`R`）重複這一段：TRACK 播到段落結尾跳回開頭，LIVE 在最後一句之後接回第一句；再按一次或跳到別段就結束
   - 下：波形時間軸，含段落、歌詞刻度、操作提示；點擊或拖曳可以跳轉
   - 右：設計（主視覺概念、每段設計理由與快速修改）、研究（研究報告與來源）、控制（黑場等安全控制固定在頂端、場景覆寫、亮度、字級）、同步（偏移、BPM、Tap tempo、麥克風）
   - 按快捷鍵時，預覽下方會短暫顯示提示（HUD），頂欄的狀態膠囊顯示黑場、歌詞隱藏、凍結等目前狀態；這些只在控制台出現，不會出現在投影視窗
   - 「重新設計」：輸入指示（例如「副歌更熱血」「換成冷色調」），AI 會依指示重新設計
4. **投影視窗**：按控制台的「開啟投影視窗」（或按 `O`），把新視窗拖到投影機／LED 螢幕，再在那個視窗**按 `F` 或雙擊**進入全螢幕。滑鼠停 2 秒後游標會自動隱藏。
5. **歌詞編輯器** `/p/<id>/lyrics`：修改歌詞與時間、對拍（播放時按空白鍵標記每一句開始）、±0.1 秒微調、匯出 LRC。右上角「⋯」選單可以切換外觀（跟隨系統／淺色／深色）。

### 樂團、視覺聖經與演出

- 首頁的「樂團」建立樂團。樂團頁 `/b/<id>` 有**視覺聖經**（世界觀、色盤、字體、偏好與避免的場景、素材處理、歌詞政策、要與不要）、**演出**、旗下的**作品**與共用的**樂團素材**。
- 「從作品產生視覺聖經」：設計師讀樂團已設計好的歌，整理出共同的配色、字體與場景；之後在 `/b/<id>/bible` 逐項修改。樂團的歌重新研究或設計時，都會把視覺聖經當成硬性規範。
- 歌可以在新作品卡片的「樂團」選單、或作品卡的「⋯ › 指定樂團…」加入樂團；樂團的歌也能用樂團素材。
- 演出 `/s/<id>`：把歌排成歌單，加入進場、串場、待機、散場畫面（場景、樂團色盤、素材、畫面文字）；拖曳把手或用上下鍵調整順序，顯示總長度與每首歌是否可上台；「套用到所有歌曲」把場地的輸出畫面套到每首歌；「整場弧線」排出每首歌的能量與配色重心，可逐首或一次依弧線重新設計。

每一頁左上角的「‹ 作品庫」都會回到首頁。首頁、設計總覽與歌詞編輯器跟隨系統的淺色／深色外觀；控制台永遠是深色。

### 演出模式（整場演出）

演出頁 `/s/<id>` 右上角的「開始演出」會先檢查每首歌是否可上台（還沒準備好的歌會列出來，可以選「仍要開始」），再進入**演出控制台** `/s/<id>/live`：

- **開演前**：按「開啟投影視窗」（或 `O`）打開整場演出共用的投影視窗 `/s/<id>/output`，拖到投影機／LED 螢幕後按 `F` 全螢幕。整場只需要這一個投影視窗，頂欄會先顯示「投影已連線」。
- **演出清單**（左側）：每個項目的類型、名稱、長度、準備狀態與弧線角色。紅色是**播出中**，藍框是**待命**（下一次 GO 會播出的項目）；GO 之後自動待命下一個項目；點任何一列就改成待命那一個（播出中的項目也可以，再按 GO 就從頭重播）。播出中的歌曲下方會顯示整場弧線給這首歌的角色、能量與說明（只在控制台）。
- **GO**（`G` 或左上角的大按鈕）播出待命的項目，按鈕上寫著會播出什麼。換場預設「淡出淡入」（投影畫面淡到全黑、約 0.8 秒後淡入下一個），也可以改成「直接切換」。GO 之後 0.8 秒內再按不會有反應，避免連按跳過一首。
- 播出中的是**歌曲**時，右邊就是完整的歌曲控制台（和 `/p/<id>` 相同）；歌曲停在開頭，按空白鍵開始。打開「GO 後自動播放」則 GO 之後直接開始播放（TRACK 模式）。
- 播出中的是**進場、串場、待機或散場畫面**時，右邊是畫面控制台：預覽、已播出時間、預計長度的倒數（時間到不會自動換場，畫面會一直循環到下一次 GO）、畫面文字、下一個項目，以及黑場、文字、凍結、場景覆寫、亮度等安全控制。
- **待機畫面**：任何時候按 `S`（或左下角的按鈕）都會立刻切到待機畫面；演出沒有自己的待機畫面時，使用樂團配色的安全畫面。之後點演出清單裡的歌再按 GO，就能從頭重新開始那首歌。
- **黑場**（`B`）是整場的總開關：黑場中按 GO，下一個項目也維持全黑，直到再按 `B`。
- 待命的項目會預先載入（歌曲的設計與音檔，投影視窗也先載入字型與素材），GO 時不用等待。
- 控制台分頁不小心重新整理時，會回到播出中的項目（歌曲的位置、覆寫、保持與循環都會還原），投影視窗會自動重新同步，不需要重開。「淡出淡入／直接切換」與「GO 後自動播放」依每場演出記住。演出控制台與投影視窗開著時，螢幕不會進入休眠（瀏覽器支援時）。

### 兩種播放模式

- **TRACK**：跟著音檔播放，歌詞與畫面依時間自動走（適合放伴奏帶或對時排練）。
- **LIVE**：現場樂團不跟 click 時使用。音檔不播放，由操作員按空白鍵或 `→` 逐句下 cue，畫面跟著切換段落；可開麥克風讓動畫跟著現場音量律動，並用 `T` 打拍子。

## 同步與控制器（MIDI、MIDI clock、MTC、LTC）

控制台預設是**手動**：鍵盤逐句、逐段操作，不需要任何 MIDI 或麥克風權限。需要跟播放端同步或用實體控制器時，在「同步」分頁（演出控制台的畫面與開演前頁面：頂欄的「同步與控制器」按鈕）設定：

- **同步來源**：手動／MIDI clock／MTC／LTC。大方塊顯示狀態：綠色**鎖定**、黃色**自由運轉**、紅色**中斷**、灰色等待訊號，以及時間碼 `HH:MM:SS:FF`、幀率、BPM、歌曲位置與偏移。頂欄的膠囊（例如「MTC 鎖定」「MIDI clock 128 BPM」「時間碼中斷」）只在控制台，投影視窗看不到。
- **MIDI clock**（節拍模式）：跟著 Ableton Live、Logic、QLab 等送出的 MIDI clock 律動（24 ppqn，平滑掉抖動），支援 Start／Stop／Continue 與歌曲位置。鎖定時畫面的拍點優先跟著它，其次才是麥克風與 Tap tempo；超過半秒沒有訊號就算中斷。
- **時間碼**（MTC 或 LTC）：一首歌一小時，時間碼 `01:00:00:00` 是第 1 首歌的開頭（每首歌可以在「同步」分頁改起點；演出時由演出頁決定：歌曲的「⋯ › 設定時間碼…」，預設依歌單順序）。TRACK 模式控制台的音檔跟著時間碼走（誤差超過 0.08 秒就重新對齊，跟著播放與停止）；LIVE 模式時間碼直接帶動時間與有時間碼的歌詞。單一格亂跳的時間碼不會讓歌跳走（要連續 3 格才重新定位）。時間碼中斷時先「自由運轉」（預設 2 秒，可調 0.5 到 10 秒），超過就**切回手動**並停在原本那一句，顯示「時間碼中斷，已切回手動」；訊號回來會自動重新鎖定。跟隨時間碼時，手動換句要先按 `X` 回到手動。
  - **MTC**：MIDI Time Code（24／25／29.97 DF／30 fps，補償約 2 格的傳輸延遲）。「MTC 定位（SysEx）」讓播放端停止或跳位時立刻定位，需要另一個 MIDI 權限，所以預設關閉。
  - **LTC**：從音訊輸入解碼（錄音介面的一個聲道；瀏覽器的回音消除、降噪與自動增益都會關閉）。自動偵測 24／25／30 fps 與 drop-frame，承受音量變化、雜訊與 ±1% 的速度誤差；「輸入電平」與「時間碼在第 n 聲道」協助接線。
- **演出控制台的「跟隨時間碼換歌」**（演出清單的開關）：時間碼進入某首歌的小時，就用設定的換場方式播出那首歌；進場、串場等畫面仍由 GO 播出。
- **控制器**（「控制器…」）：按「學習」，再按控制器上的按鍵、打擊墊、踏板或推桿，就對應完成（音符或 CC，含聲道）。每個快捷鍵的動作都能對應（GO 與待機只在演出控制台）；推桿可以調「畫面強度」「歌詞字級」與「最高亮度」（只會在 LED 安全預設的上限以下調整）。會列出重複使用的按鍵、可逐項清除，最上方顯示剛收到的訊息。按鍵只在按下時動作、放開不算，連按會被過濾（GO 與待機多等 0.15 秒），CC 當按鍵時超過 64 才觸發。
  - 預設對應：**ProPresenter 式**（音符 n 送出第 n 句，可設聲道與偏移）與**段落音符**（從起始音符往上，每個音符跳到一個段落）。
  - 對應記在這台電腦的瀏覽器裡，所有歌曲與演出共用；用「匯出 JSON」「匯入 JSON…」帶到別台電腦。
- **瀏覽器**：MIDI 需要 Chrome 或 Edge（Safari 與所有 iPhone 瀏覽器都不支援 Web MIDI；Firefox 需要另外允許）。LTC 用音訊輸入與 AudioWorklet，在 Chrome、Edge 使用（Safari 理論上支援，但還沒有實測）。

## 免費研究與「用 claude.ai 研究」（不用 API 費用）

沒有 `ANTHROPIC_API_KEY` 時，研究步驟就是**免費研究**，設計總覽的研究串流會顯示「查詢 MusicBrainz…」「讀取維基百科…」「分析歌詞意象…」：

- **公開資料**：從 [MusicBrainz](https://musicbrainz.org)（曲風標籤、首次發行年份、專輯、國家、樂團類型、官方連結）與維基百科（中文優先、臺灣正體，查不到再用英文）找樂團與這首歌。兩個來源同時查詢，每個請求最多 6 秒、整體最多約 15 秒，MusicBrainz 每秒最多一次；查到的資料存在作品上，之後重新研究會沿用（30 天內）。來源查不到或連不上時（例如很新的獨立樂團）照樣完成，只是改依歌詞與音訊推論。
- **本機分析**（不上網、每次結果都一樣）：歌詞的意象（海、浪、夜、城市、光、雨、風、火、星、路……約 50 類，各自對應配色、場景與動態）、情緒（正向程度與激昂程度，副歌的 hook 加權）、人稱（我／你／我們）、最適合大合唱的短句；音訊的速度、能量起伏、亮度與低頻，歸納成「爆發釋放」「冷冽推進」「溫暖律動」「陰鬱緩慢」「溫柔漂浮」；以及曲風的視覺語法（後搖滾、shoegaze、city pop、獨立搖滾、民謠、金屬、電子、嘻哈、dream pop、math rock、龐克……共 20 種：配色傾向、場景、歌詞多寡、轉場力道、字體）。
- **結果**：一份和 Claude 一樣五個段落的研究簡報（附來源連結，標示「免費研究（公開資料＋歌詞與音訊分析）」），設計方案與設計方向的配色、場景、母題、歌詞樣式、概念文字與操作提示都依這些發現產生，仍然遵守樂團視覺聖經、參考圖配色與 LED 安全模式。
- 有 API 金鑰時仍由 Claude 研究；「重新設計」可以打開「這次用免費研究（不呼叫 Claude API）」。

**用 claude.ai 研究**（設計總覽左側，或「設計方向」的「用 claude.ai 提案」）用你自己的 claude.ai 帳號，不需要 API 金鑰：

1. 按「複製提示詞」。提示詞包含歌曲資料、分段的歌詞、音訊分析、免費研究的發現、樂團視覺聖經、參考圖說明、輸出畫面與 LED 安全限制，以及和 Claude API 相同的設計規範與 JSON 格式。提示詞太長、免費版的回覆被截斷時，改用「精簡版」。
2. 按「打開 claude.ai」，在新對話貼上送出；有參考圖時依圖號附上圖片，看得到「網頁搜尋」就打開。
3. 用回覆下方的「複製」按鈕複製 Claude 的整則回覆，貼回來按「套用」。Livelyrics 會找出 JSON（容許前後的說明文字、智慧引號、結尾逗號等小問題），用和 API 相同的規格檢查與修正，研究簡報也一起存下。
4. 有問題時會用中文列出哪裡不對，按「複製修正提示詞」貼回同一個 claude.ai 對話，再把新的回覆貼回來。套用後可以「復原」回到原本的方案。

貼上的內容只會被當成文字檢查，不會被執行，上限 200 KB。

免費研究做不到的：它不會看 MV 或現場影片（專輯封面會從 Cover Art Archive 下載，見下方「研究找到的素材」），也不會讀樂評與樂迷討論；公開資料只有曲風、年份、專輯與百科摘要，冷門樂團常常查不到；歌詞分析是詞庫比對，讀不出反諷、隱喻與上下文；設計是規則推導，只看得懂簡單的指示。需要這些時用「用 claude.ai 研究」或設定 API 金鑰。

選用的環境變數：`LIVELYRICS_FREE_SOURCES=off`（不查公開資料，也不查 Cover Art Archive）、`LIVELYRICS_MUSICBRAINZ_URL`、`LIVELYRICS_WIKIPEDIA_URL`（改用自架或測試用的端點，後者可含 `{lang}`）、`LIVELYRICS_COVERART_URL`（Cover Art Archive 的替代端點，預設 `https://coverartarchive.org`）、`LIVELYRICS_VISUALS=off`（研究時完全不下載樂團素材）。

## 研究找到的素材

設計要看得出是**這個樂團、這張專輯、這支 MV**，所以研究時會順便把樂團真實的視覺素材找回來：

- **專輯／單曲封面**：從 MusicBrainz 找到這首歌所在的專輯，再到 [Cover Art Archive](https://coverartarchive.org) 下載正面封面（免費研究與 Claude 都會做）。
- **有 Claude（API 金鑰）時**：Claude 在研究簡報之外另外列出官方 MV、主視覺／巡演海報、標誌與過去的現場照片，可以用網頁擷取打開官方網站找到真正的圖片網址。YouTube 的 MV 會取影片的高解析截圖（`maxresdefault.jpg`，沒有時用 `hqdefault.jpg`）；只有網頁沒有圖片網址時，讀那一頁的分享圖（og:image）。
- **設計會用它們**：每一張都是設計參考——Claude 設計主視覺、設計方向與專屬畫面時會真的看到這些圖（連同參考圖），並被要求從封面、MV、主視覺取配色、母題、構圖與材質；離線設計師用伺服器量出的顏色（封面最重）決定配色。標「可以上台」的素材還能成為段落的素材（例如開場讓封面以雙色調浮現、橋段用印刷網點回到封面），有節制地只放在一兩個段落。
- **設計總覽的「研究找到的素材」**（控制台的「研究」分頁也有）：每張圖顯示種類、來源連結與量到的顏色，可以切換「可以上台」／「只當參考」或「移除」。移除會同時從設計參考與舞台上拿掉（用到它的段落改回只用場景），重新研究也不會再加回來；重新研究時已有的素材保留你的選擇，不會重複下載。

**授權**：素材是樂團自己的作品，要先按一次「確認樂團授權…」（存在樂團上，樂團的每一首歌都適用；沒有樂團的歌存在這首歌上）。確認之前，收集照常進行，但每一張都預設「只當參考」、不會上台；確認之後新找到的素材預設「可以上台」，每一張仍然可以改。每張素材都記錄來源頁面、圖片網址、由誰找到、下載時間與當時的授權狀態。

**下載的安全規則**（網址來自網路與 Claude 的回覆，一律當成不可信）：只接受 https（443 埠、不能帶帳號密碼）；先解析 DNS，任何一個位址是內部網路、本機、link-local（含雲端 metadata 169.254.169.254）、CGNAT、多播、保留或文件用的 IPv4／IPv6（包括 IPv4-mapped、NAT64、6to4 內嵌的位址）就拒絕，`localhost`、`*.local`、`*.internal` 與沒有點的主機名稱連查都不查；連線使用檢查過的位址（避免 DNS rebinding）；最多轉址 3 次，每一次都重新檢查；每張圖 8 秒逾時、8 MB 上限（宣告的長度與實際下載都檢查）；回應必須是圖片類型，而且檔頭必須是 JPEG／PNG／WebP／GIF（SVG 一律拒絕、不會被執行或顯示）；太小的圖（圖示、預留圖）略過；同一個網址或同樣內容的圖只收一次，每首歌最多 8 張；整個收集最多 30 秒，雲端模式還會留時間給研究步驟存檔（每個步驟 300 秒內）。收集失敗只會記在處理紀錄裡，研究照常完成。設定的測試端點（`LIVELYRICS_COVERART_URL`）是唯一可以用 http 與本機位址的例外。

## 設計方向與樂團確認

專業的舞台視覺設計師不會只交一個方案：先提出 2 到 3 個明顯不同的方向給樂團選，選定後才開始製作。設計總覽 `/p/<id>/process` 的「設計方向」區塊就是這個流程（不用也可以，原本的「重新設計」照常運作）：

- **參考圖**：把樂團喜歡的畫面拖進「參考圖」（專輯、電影劇照、海報、別人的舞台照都可以，每首歌最多 12 張），點一張圖寫一句說明，例如「喜歡這個顏色」「這種顆粒感」。圖片會在瀏覽器縮成 1024 px 的 WebP 再上傳，並量出主色、亮度與飽和度。樂團頁 `/b/<id>` 也有「參考圖」，會套用到樂團的每一首歌（在歌曲上以「樂團」標示）。參考圖只給設計師看，**不會出現在舞台上**。
- **提出設計方向**：設計師一次提出 2 到 3 個方向（例如 A 冷調膠片感、B 飽和拼貼、C 黑白極簡）。每個方向有名稱、一句話提案、引用研究與參考圖（「圖 2 的顆粒感」）的理由、配色、字體、場景傾向與歌詞處理，並展開成完整的設計方案。Claude 會真的看參考圖；沒有設定 Claude 時，離線設計師依冷暖、飽和、黑白三個軸線提案，配色取自參考圖量到的顏色，並依免費研究找到的曲風與歌詞意象調整（例如民謠會有一個暖色大地色的膠片方向）；也可以按「用 claude.ai 提案」請你自己的 claude.ai 提出方向。歌曲屬於樂團時，三個方向都遵守樂團的視覺聖經。
- **方向比較**：三張卡片並排，每個方向有 3 到 4 張**風格畫面**（前奏、第一次副歌、橋段、最後副歌），由和匯出影片相同的渲染器在瀏覽器算出，套用這首歌的 LED 安全模式與輸出畫布比例。點畫面可以放大檢視。
- **採用這個方向**：它就成為這首歌的設計方案（已經開著的控制台重新整理一次就會使用它）；原本的方案會保留，按「復原」就回來。也可以在卡片寫下樂團的意見、「修改」（設計師依意見修改這個方向，和「重新設計」同一條路）或「退回」。
- **一頁提案** `/p/<id>/proposal`：把所有方向排成一張 A4 橫式的提案單（風格畫面、配色、字體樣張、提案與理由、參考圖，以及「選擇方向 A／B／C、意見、簽名／日期」），按「列印／存成 PDF」存成 PDF 傳給樂團。

目前沒有提供「下載 PNG」（需要額外的網頁轉圖片套件），請用 PDF；也還沒有給樂團的免登入分享連結（需要簽章、會過期的唯讀連結，列為之後的工作）。風格畫面只存在瀏覽器（重新整理後會重新算出，約數秒），不佔用雲端空間。

## 字體藝術與排版

每一句歌詞都會出現，而且每一句都是一張排好的構圖，不是卡拉 OK 字幕。

- **字體語言**：設計師為每首歌選一種——**日系 MV 字卡**（巨字與小字的極端對比、直橫混排、大量留白、在拍點上硬切）、**電影片頭／動態海報**（出血的巨字、網格、細線與編號、遮罩擦出）、**書法與水墨**（楷書依筆順寫出、暈染與飛白、一方紅印）、**實驗／故障感**（切片、RGB 分離、殘影、疊印與顆粒，閃爍仍在 LED 安全限制內）。Claude、免費研究的離線設計師（依曲風與音訊情緒：龐克、math rock 用故障感，民謠用水墨，city pop 用片頭，後搖與 shoegaze 用大量留白的字卡）、設計方向（三個方向三種字體語言）與「用 claude.ai 研究」都會設計它。
- **每一句的構圖**：巨字＋小字、直排欄、直橫交錯、網格詩、出血、散落、海報堆疊、鏤空窗、書寫、殘影、撕裂、低語、片名卡。重複的副歌沿用同一個構圖讓全場認得，最後一次副歌放大；主歌安靜、副歌大、橋段換一種語彙。構圖守住最小字級、閱讀順序、中文直排標點與禁則（不在詞中間或「的、了」前面斷行），避開畫面下緣，翻譯不會壓到歌詞，16:9、32:9 超寬 LED 與 9:16 直式都排得下（直式畫面會把巨字立起來，超寬畫面讓每一句靠向一側）。
- **排版** `/p/<id>/type`：設計總覽、控制台頂欄與設計分頁都有「排版」。整首（字體語言、每個參數、字體、配色處理、裝飾、「重新生成全部構圖」）、段落（覆寫構圖、排列、大小、動態）、這一句（構圖縮圖、「換一個構圖」、點字設定強調字、排列、動態意象、進出場、拖曳或方向鍵移動、大小、角度、顏色：自動／主字色／點綴色／反白／鏤空、鎖定、「重設為生成的」）。預覽就是投影的渲染器，可以「從這句播放」、比較「調整後／生成的」；每一步都能復原，自動儲存，控制台與投影視窗開著時會立刻看到。手機上也能用（44 px 的按鈕、分頁與歌詞清單）。
- 舊的作品（這個版本以前設計的）維持原本的歌詞樣式；排版頁可以「建立字體語言」。

## 專屬畫面（每首歌自己的生成畫面）

每首歌的背景不再是「同一個特效換顏色」：設計完成後多一個「畫面」步驟，為這首歌寫一支專屬的生成畫面程式（GLSL）。有 Claude 時由 Claude 依研究、歌詞、音訊、視覺聖經與參考圖設計：一個主角形狀、清楚的留白、節制的亮部、隨歌曲弧線演變（主歌稀疏、副歌打開、橋段換規則）；沒有 API 金鑰時由離線作曲器依曲風、歌詞意象與音訊情緒組合「形狀 × 質地 × 構圖 × 動態」，不同的歌有不同的畫面結構。

- 歌詞和畫面一起構圖：每一段都有文字區（畫面的留白），歌詞只排在裡面；字與畫面的關係可以是留白、切開（字從亮的形狀裡挖空）、穿過後方或被照亮。大部分句子是中小字、排在網格上，只有少數重點句（歌名那一句、副歌的 hook）才會放大。
- 設計總覽的「專屬畫面」：主視覺靜止畫面（副歌裡的一格）、概念、每段的畫面，「重新產生畫面…」（可以寫一句指示）與「使用專屬畫面」開關（關掉就回到每段的內建場景，程式會保留）。
- 排版編輯器的段落面板可以移動文字區、改變字與畫面的關係。
- 安全：程式在伺服器與瀏覽器都會先經過檢查（沒有前處理指令、只能用系統提供的 uniform 與取樣輔助、迴圈次數有上限…），畫面仍然經過 LED 安全模式；在這台電腦無法編譯或太耗效能時，自動改用內建場景，控制台預覽會提示。
- 舞台實驗室：`/stage-lab?program=<範例 id>`（night-drive、tidal-flat、monolith、enso、signal）或 `program=composer:<形狀>` 看每一種畫面。

## 匯出影片（給音樂祭的媒體伺服器）

有些音樂祭要求事先交影片，在他們的 Resolume／disguise 上播放。控制台頂欄的「匯出」（或設計總覽的「匯出影片」）會在新分頁打開匯出頁：

- 版本：**完整**（場景＋素材＋歌詞）、**背景**（無歌詞）、**歌詞層**（黑底白字 luma matte；瀏覽器支援時可選透明 VP9 WebM）。三個版本逐格對齊。
- 規格：尺寸就是控制台「輸出畫面」設定的畫布；影格率 25／29.97／30／60；H.264 MP4（不支援時自動改用 VP9 WebM）；畫質標準／高／最高；範圍整首、段落範圍或自訂；可附上音訊（排練預覽用，交件時關閉）。
- 先按「單格預覽」確認某一格的字型、素材和歌詞位置，再開始匯出。每一格都照歌曲時間算出，和投影畫面一致。
- 開啟「直接存到資料夾」時邊算邊寫入（長片、4K 也不會吃光記憶體）；另外會輸出時間表 CSV（段落、歌詞行、操作提示）與說明文字檔。
- 匯出時讓分頁留在前景（螢幕會保持開啟）。

## LED 安全模式

音樂祭的 LED 牆非常亮。大面積的閃白、光暈、跟著拍點的快速閃爍與整片明暗翻轉，會讓前排觀眾短暫看不見，也可能引發光敏性癲癇。Livelyrics 預設開啟 **LED 安全模式**（新作品與舊作品都是開啟、「LED 牆 70%」）：

- **亮度上限**：室內投影 100%、LED 牆 70%、戶外強光 LED 55%，或自訂 20% 到 100%。上限套用在整個畫面：場景、樂團素材與歌詞都一樣。「柔化亮部」再壓低最亮的部分，降低大面積的明暗反差。
- **閃爍限制**（WCAG 2.3.1）：任何一秒內最多 3 次大面積閃爍（明暗變化至少 10%、較暗的一側低於 0.8、面積達到約四分之一個視野）。快要超過時，畫面會暫時改成緩慢的淡變，直到來源不再快速閃爍；控制台會顯示「已抑制閃爍」與每一段抑制了幾次。
- **紅閃保護**：飽和紅色的明暗變化另外計數，每一次都算一次紅閃，並減弱紅色畫面的脈動。
- **從設計端就少要危險的東西**：閃白與光暈綻放轉場改成淡入，音樂反應最多 50%，拍點脈動每秒最多 3 次，巨字衝擊的字卡切換放慢。設計分頁的「LED 安全檢查」與匯出頁會列出這首歌哪些段落因此調整。
- **設定位置**：控制台「控制」分頁最上方的安全控制（和黑場放在一起）與下方的「LED 安全模式」；頂欄的膠囊顯示「LED 安全 70%」。設定跟著「輸出畫面」存在每首歌，演出頁的「輸出畫面」可以設定整個場地，再用「套用到所有歌曲」套用。
- **關閉要確認**：關閉前會先說明風險；關閉後頂欄膠囊變成橘色的「LED 安全已關閉」。
- **LED 模擬**：控制台預覽右下角的「LED 模擬」把預覽畫成 LED 牆（選 P2.6／P3.9／P4.8／P6 間距與牆寬，可放大檢視），用來判斷歌詞在 LED 解析度下是否清楚。只在控制台，投影視窗不會出現。
- **匯出**：影片預設套用同樣的設定（完整與背景版本；歌詞 matte 是鍵控訊號，不降亮度），時間表與說明文字檔會寫明使用的設定。要匯出沒有保護的影片必須再確認一次。

它能做到與不能做到的：安全模式會降低風險，並依 WCAG 2.3.1／ITU-R BT.1702 的門檻限制閃爍，但**不是經過認證的光敏性癲癇（PSE）檢測**。閃爍是在縮小的亮度格點上估算，歌詞層（網頁文字）的亮度是估計值；LED 牆本身的亮度、色溫與處理器設定也會影響結果。要在電視播出或對安全有正式要求的場合，請用 Harding 類的分析工具檢查匯出的影片，並在現場與 LED 廠商確認牆面亮度。

## 演出前檢查

- 演出前先在有網路的環境打開一次投影視窗，字型會被瀏覽器快取；研究（Claude 或免費研究）只在製作階段需要網路，演出時完全在本機運作。
- 用 Chrome／Edge，並讓控制台分頁保持在前景（最小化的分頁會被瀏覽器降速）。
- 控制台「控制」分頁可以開啟測試圖與安全區，確認投影比例與字級。
- 確認頂欄顯示「LED 安全」與場地適合的亮度（LED 牆 70%、戶外強光 LED 55%），並看一次設計分頁的「LED 安全檢查」；需要時打開「LED 模擬」確認歌詞在 LED 上的清晰度。
- 整場演出用演出模式：開演前先打開投影視窗並全螢幕，確認頂欄顯示「投影已連線」，再從演出清單排練一次換場（GO、`S` 待機、`B` 黑場）。
- 用時間碼或 MIDI 控制器時：確認「同步」顯示綠色「鎖定」、幀率正確，讓播放端從每首歌的開頭跑一次；按一次 `X` 確認能回到手動，並試一下控制器上的 GO、黑場與推桿。

## 開發

```bash
npm run typecheck   # next typegen + tsc
npm run lint
npm test            # vitest
npm run build
```

瀏覽器端對端測試（Playwright + Chromium）：先安裝一次 `npm i --no-save playwright && npx playwright install chromium`（不會寫進 `package.json`），再用正式版啟動一個測試用伺服器，資料放在暫存資料夾，不會動到自己的作品：

```bash
npm run build
LIVELYRICS_DATA_DIR=/tmp/livelyrics-e2e npx next start -p 3100
# 另開一個終端機：
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/e2e.cjs             # 單首歌：上傳、處理、控制台、投影
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/e2e-show.cjs        # 演出模式：GO、待機、段落保持與循環
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/e2e-led.cjs         # LED 安全模式：亮度上限與閃爍限制
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/e2e-directions.cjs  # 設計方向、參考圖與一頁提案
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/e2e-sync.cjs        # 同步與控制器：假的 MIDI 裝置、MIDI clock、MTC、LTC（假麥克風）
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/e2e-type.cjs        # 字體藝術：構圖、排版編輯器（電腦與手機）、匯出
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/e2e-scene.cjs       # 專屬畫面：投影與預覽、編譯失敗的退回、LED 安全、重新產生與開關
```

`e2e-sync.cjs` 不需要實體裝置：它在頁面裡裝一個假的 Web MIDI 輸入，並把自己產生的 LTC 音檔（25 fps，從 01:00:10:00 開始）當成 Chromium 的假麥克風。改了 `src/lib/sync/ltc.ts` 或 `ltc-worklet.ts` 後，執行 `node scripts/build-worklets.mjs` 重新產生 `public/worklets/ltc-decoder.js`（`--check` 只檢查是否過期；單元測試也會檢查）。

免費研究、研究找到的素材與「用 claude.ai 研究」的測試不連外部網站：伺服器改查腳本內建的測試資料來源（`fixtures/research/` 的真實回應、Cover Art Archive 的清單與 `fixtures/visuals/cover.jpg`），所以要這樣啟動：

```bash
LIVELYRICS_DATA_DIR=/tmp/livelyrics-e2e \
  LIVELYRICS_MUSICBRAINZ_URL=http://127.0.0.1:3199/musicbrainz/ws/2 \
  LIVELYRICS_WIKIPEDIA_URL='http://127.0.0.1:3199/wikipedia/{lang}' \
  LIVELYRICS_COVERART_URL=http://127.0.0.1:3199/coverart npx next start -p 3100
BASE=http://localhost:3100 SHOTS=/tmp/shots node scripts/e2e-free-research.cjs
```

commit 訊息以 `WIP:` 開頭的推送不會在 Vercel 建置（`vercel.json` 的 `ignoreCommand`），用來保存進行中的工作，不會把做到一半的版本放上預覽網址。
